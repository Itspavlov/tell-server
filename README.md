# Tell Server v2 — защита, аккаунты, личные сообщения, реакции

Что сделано: закрыто удаление сообщений посторонними, добавлена серверная проверка всех данных, защита от спама, безопасная запись истории, резервные копии.
Добавлено поверх этапа 1: аккаунты (имя + пароль, пароли только в виде scrypt-хеша), настоящие личные сообщения между двумя аккаунтами, реакции (6 эмодзи) и ответы на сообщения в общих чатах.
Что НЕ сделано (отдельные этапы): PostgreSQL, восстановление пароля, объявления на сервере, загрузка фото во внешнее хранилище, фото в личных сообщениях.

## Важно про аккаунты и личные сообщения
- Данные лежат в файлах `data/accounts.json` и `data/dms.json`. **Без Persistent Disk на Render эти файлы (и аккаунты, и личные чаты, и общая история) пропадают при каждом пересоздании сервиса.** Для реальной работы подключите Persistent Disk (платная опция Render) и задайте `DATA_DIR=/var/data`, либо переходите на PostgreSQL.
- Объявления пока лежат в приложении, а не на сервере. Диалог создаётся с владельцем по ИМЕНИ. Демо-хозяева (Александр, Мария и т.д.) — не настоящие аккаунты: переписка с ними сохранится, но ответит только тот, кто зарегистрирует такое имя. Для настоящих объявлений нужен следующий этап (объявления на сервере с привязкой к аккаунту).
- Зарегистрированное имя занято: гость не сможет писать или ставить реакции под ним в общих чатах.
- **Группы («Моя группа»):** создание, приглашение по имени зарегистрированного друга или по ссылке-коду, до 20 участников и до 10 групп на человека. В группе — сообщения, ответы, реакции и карточки объявлений. Файл `data/groups.json`. События: `group-create`, `group-list`, `group-open`, `group-send`, `group-react`, `group-invite`, `group-join`, `group-leave`.
- **Реакции на объявления** (`ad-react`, `ad-reactions`, файл `data/adreactions.json`) доступны и гостям. Ответ на объявление в общем чате передаётся полем `replyAd`.
- **Объявления на сервере:** `POST /api/listings` (создать или изменить, нужен вход), `DELETE /api/listings/:id` (только автор), `GET /api/listings` (лёгкий список с обложками, для всех), `GET /api/listings/:id` (полное, с фото). Автор берётся из аккаунта, поля и фото проверяются по белому списку (до 6 фото по 350 КБ, до 20 объявлений на человека). Файл `data/listings.json`, общий лимит `MAX_LISTINGS_MB` (по умолчанию 100). Старые объявления с телефона автоматически публикуются при входе. Для большого числа фото позже понадобится S3 или диск.
- Открыть список контактов телефона из браузера нельзя, поэтому друзей приглашают по имени в Tell или по ссылке.
- События: `dm-open`, `dm-list`, `dm-history`, `dm-send` (личные), `react` (реакции), в `send-message` добавлено необязательное поле `replyTo`. HTTP: `POST /api/auth/register`, `/login`, `/logout`, `GET /api/auth/me`.

## Переменные окружения (Render → Environment)
| Имя | Значение |
|---|---|
| NODE_ENV | production |
| ALLOWED_ORIGINS | https://gokurort-new.onrender.com |
| ADMIN_TOKEN | длинный секрет (32+ символов), `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| DATA_DIR | путь к Persistent Disk, например /var/data (если диск подключён) |

Без ADMIN_TOKEN админ-функции полностью выключены (это безопасный режим).
Токен храните только в Render и у себя; в Git и в клиентский код он не попадает.

## Админ-команды (PowerShell)
Очистить комнату:
`Invoke-RestMethod -Method Delete -Uri https://tell-server.onrender.com/api/messages/work -Headers @{Authorization="Bearer ВАШ_ТОКЕН"}`
Скачать копию всей истории:
`Invoke-WebRequest -Uri https://tell-server.onrender.com/api/admin/export -Headers @{Authorization="Bearer ВАШ_ТОКЕН"} -OutFile backup.json`
Журнал действий: `data/audit.log`.

## Безопасный порядок выкладки
1. Перед выкладкой скачайте копию истории (команда export выше — со старого сервера она не работает, поэтому на Render откройте Shell и скопируйте `data/messages.json`, либо хотя бы сделайте `GET /api/messages/<комната>` для каждой комнаты и сохраните ответы).
2. Локально: `npm test`, затем `npm start` и откройте сайт, указав адрес локального сервера.
3. Выкладывайте только после п.2: `git add .`, `git commit -m "server v2"`, `git push origin main`.
4. После деплоя проверьте `/healthz`, `/readyz` и отправку сообщения с сайта.
5. Сначала сервер, потом клиент (сервер совместим со старым клиентом).

## Откат
Render → Deploys → предыдущий деплой → Rollback. Либо в репозитории: `git revert <коммит>`; либо временно запустить `legacy/server.v1.js` (команда start: `node legacy/server.v1.js`).
История: при каждом старте в `data/backups/` создаётся копия (хранятся последние 20). Восстановление: остановить сервер, скопировать нужную копию поверх `data/messages.json`, запустить.

## Важно
Без Persistent Disk Render стирает файлы при каждом пересоздании сервиса — это ограничение хранения в файле, а не новой версии. Для надёжной истории нужен диск или PostgreSQL (этап 3).
Лимиты и IP хранятся в памяти одного процесса: при нескольких инстансах понадобится общее хранилище (Redis).

## Проверенные хозяева (кто может размещать жильё)

Публиковать объявления могут только аккаунты со статусом «проверенный». Статус выдаёте вы:
пользователь подаёт заявку в приложении (Профиль → «Добавить жильё» → «Подать заявку»), вы смотрите заявки и подтверждаете.
Нужна переменная `ADMIN_TOKEN` на Render. Токен никому не показывайте.

PowerShell (подставьте свой токен вместо ТОКЕН):

```powershell
$h = @{ Authorization = "Bearer ТОКЕН" }
# кто подал заявки
Invoke-RestMethod -Uri https://tell-server.onrender.com/api/admin/verify-requests -Headers $h
# подтвердить хозяина (имя как в приложении)
Invoke-RestMethod -Method Post -Uri https://tell-server.onrender.com/api/admin/verify -Headers $h -ContentType 'application/json' -Body '{"name":"Имя","verified":true}'
# снять статус
Invoke-RestMethod -Method Post -Uri https://tell-server.onrender.com/api/admin/verify -Headers $h -ContentType 'application/json' -Body '{"name":"Имя","verified":false}'
```

Чтобы разместить объявление самому, сначала подтвердите свой аккаунт этой командой.
Объявления, уже опубликованные до введения проверки, остаются на месте.
Все выдачи статуса пишутся в журнал аудита (`audit.log`).

## Удаление личных диалогов

Событие `dm-delete {convId}` — «удалить у себя»: у собеседника переписка остаётся, у вас она пропадает;
если собеседник напишет снова, диалог вернётся, но старые сообщения — нет.

## Панель модерации `/admin`

Открывается по адресу `https://tell-server.onrender.com/admin` (работает только если задан `ADMIN_TOKEN`).
Вход — ваш `ADMIN_TOKEN`; он хранится только в открытой вкладке и пропадает при её закрытии.

Что умеет:
- **Заявки** — подтвердить или отклонить проверку хозяина.
- **Пользователи** — поиск, выдать/снять статус «проверенный», заблокировать (сессии сбрасываются, вход закрыт), стереть все сообщения человека.
- **Чаты** — просмотр комнат, удаление сообщения (у всех исчезает сразу), кнопка «Спамер» (стереть все сообщения автора и заблокировать), очистка комнаты, автообновление.
- **Объявления** — просмотр всех объявлений с владельцем и телефоном, удаление любого, блокировка хозяина.
- **Журнал** — кто и что делал в админке (тексты сообщений в журнал не пишутся).

Защита: страница отдаётся со строгой CSP (только свои скрипты, без инлайна), чужой текст выводится как текст, а не HTML;
после 10 неверных токенов с одного адреса вход закрывается на 15 минут; каждое действие пишется в `audit.log`.

Личные сообщения и группы в панели **не показываются** — это переписка пользователей.
Блокировка действует на аккаунты. Гость без аккаунта блокируется только удалением его сообщений.
